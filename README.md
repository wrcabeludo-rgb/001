# Puzzle Quest — Match-3 казуальная игра для Android

Мобильная казуальная Puzzle-игра (Match-3) на Unity/C# с системой уровней,
звёзд, монет/кристаллов, лайвов и усилений (power-ups).

## Технологии

- **Unity 2022.3 LTS** (проверено на `2022.3.21f1`, подойдёт любая версия 2022.3.x LTS)
- **C#**, весь игровой код — в `Assets/Scripts`
- **Android**: минимальная версия API 26 (Android 8.0), таргет — Auto, IL2CPP + ARM64
- Никакой сторонней графики/аудио не требуется — все плитки и UI строятся кодом
  (см. раздел «Архитектура» ниже), поэтому APK получается компактным (обычно < 30 МБ
  без учёта самого движка Unity).

## Быстрый старт

1. Установите **Unity Hub** и Unity **2022.3 LTS** (через Hub, с модулем **Android Build Support**,
   включая Android SDK & NDK Tools и OpenJDK).
2. В Unity Hub нажмите **Open** → выберите папку репозитория (там, где лежит `Assets/`).
   Unity сам создаст недостающие файлы `ProjectSettings` при первом открытии.
3. После открытия проекта выполните пункты меню **Puzzle Game**:
   - `Puzzle Game → Создать сцены (Create Scenes)` — создаёт `MainMenu.unity`,
     `LevelMap.unity`, `GameScene.unity` в `Assets/Scenes/` и добавляет их в Build Settings.
   - `Puzzle Game → Настроить Android Player Settings` — выставляет minSdk=26,
     IL2CPP, ARM64, Gradle build system.
4. Откройте `Assets/Scenes/MainMenu.unity` и нажмите **Play** — игра полностью
   играбельна прямо в редакторе (мышь = свайп пальцем).
5. Для сборки APK: **File → Build Settings → Android → Switch Platform**, затем **Build**
   (или **Build And Run** при подключённом устройстве/эмуляторе с Android 8.0+).

> Почему сцены создаются инструментом, а не лежат в репозитории как `.unity`-файлы?
> Бинарные/YAML-файлы сцен и префабов Unity надёжно генерируются только самим редактором.
> Вместо того чтобы поставлять потенциально хрупкие вручную собранные файлы, весь UI и
> состав сцены строятся кодом при старте (`MainMenuUI`, `LevelMapUI`, `GameHUD` в
> `Assets/Scripts/UI`). Это гарантированно открывается и работает в любой копии Unity
> нужной версии, а `SceneBuilder` — это просто однократный скрипт, который создаёт
> пустые сцены с одним объектом-загрузчиком (`Bootstrap`).

## Управление

- **Свайп** по плитке (мышь/палец) — поменять её местами с соседней.
- Кнопки усилений внизу экрана: выбрать усиление → тапнуть по плитке-цели
  (для Бомбы/Молнии) или применяется мгновенно (Заморозка).

## Структура проекта

```
Assets/
  Scripts/
    Core/       — GameManager, SaveManager, CurrencyManager, LivesManager,
                  AudioManager, AdManager (заглушка AdMob)
    Data/       — TileType, ObjectiveType, LevelObjective, LevelData,
                  LevelDatabase, PlayerProgressData
    Grid/       — Tile, PuzzleGrid (ядро Match-3), TileSpriteFactory
    Level/      — LevelManager (ходы/очки/цели/победа/поражение)
    PowerUps/   — PowerUpType, PowerUpManager
    UI/         — UIWidgets (билдер UI), UIManager (оверлей+попапы),
                  MainMenuUI, LevelMapUI, GameHUD

  Resources/
    Levels/     — level_01.json … level_20.json (баланс уровней)
  Scenes/       — создаются SceneBuilder'ом (MainMenu, LevelMap, GameScene)
```

## Игровая механика

- Поле 5×5 (уровни 1–8) или 6×6 (уровни 9–20), 4–6 цветов плиток в зависимости
  от уровня.
- Свайп двух соседних плиток; ход засчитывается только если возник матч.
  Иначе плитки анимированно возвращаются на место.
- Совпадение из **3** плиток — обычное удаление + очки.
- Совпадение из **4** плиток создаёт **Молнию** (уничтожает всю строку при активации/срабатывании).
- Совпадение из **5+** плиток или Т/Г-образное пересечение создаёт **Бомбу**
  (взрывает область 3×3).
- После удаления плиток верхние падают вниз (гравитация), пустые клетки
  заполняются новыми плитками сверху — реализовано в `PuzzleGrid.CollapseAndRefillRoutine`.
- Если на поле не осталось возможных ходов — поле автоматически перемешивается
  (`PuzzleGrid.ShuffleBoard`).

## Система уровней и прогрессии

- **20 уровней** (`Assets/Resources/Levels/level_01.json` … `level_20.json`),
  легко расширяется — добавьте `level_21.json` и увеличьте `LevelDatabase.LevelCount`.
- У каждого уровня: размер поля, число цветов, лимит ходов (15–27),
  пороги очков для 1/2/3 звёзд, награда монетами/кристаллами и одна-две цели:
  - `CollectColor` — собрать N плиток определённого цвета;
  - `ReachScore` — набрать N очков (используется на каждом 5-м уровне).
- Прогресс (пройденные уровни, лучшие очки, звёзды, открытый уровень) сохраняется
  через `SaveManager` в `PlayerPrefs` (JSON через `JsonUtility`).
- Экран **LevelMap** показывает список уровней со звёздами и блокировкой
  ещё не открытых.

## Валюта, лайвы и магазин

- **Монеты** — начисляются за прохождение уровня (`coinReward`), тратятся на усиления.
- **Кристаллы** — премиальная валюта (награда за 3 звезды на некоторых уровнях,
  условная покупка в магазине, восстановление лайвов).
- **Лайвы**: максимум 5, тратится 1 за начало уровня, восстанавливается
  по 1 каждые 20 минут (`LivesManager`), либо мгновенно за 20 кристаллов.
- **Магазин** (`UIManager.ShowShop`) — покупка усилений за монеты, условная
  покупка кристаллов (без реального биллинга — задел под Google Play Billing).

## Усиления (Power-ups)

| Усиление  | Эффект                          | Стоимость          |
|-----------|----------------------------------|---------------------|
| Бомба     | Взрывает область 3×3             | 150 монет / 10 кристаллов |
| Молния    | Уничтожает всю строку            | 150 монет / 10 кристаллов |
| Заморозка | +5 дополнительных ходов на уровне | 100 монет / 6 кристаллов  |

Логика — `PuzzleGrid.ActivateBombAt/ActivateLightningAt`, инвентарь —
`PowerUpManager`, использование в UI — `GameHUD`.

## Реклама и Google Play (заготовки)

- `AdManager` (`Assets/Scripts/Core/AdManager.cs`) — интерфейс `ShowRewardedAd` /
  `ShowInterstitial`, сейчас симулирует показ рекламы (задержка + успех).
  Чтобы подключить настоящий Google AdMob SDK — установите
  Google Mobile Ads Unity plugin и замените тело методов вызовами
  `GoogleMobileAds.Api.RewardedAd`/`InterstitialAd` (комментарии в файле).
- Google Play Games Services: `applicationIdentifier` уже задан
  (`com.puzzlegame.quest`) в `ProjectSetup`; для полноценной интеграции
  добавьте Google Play Games plugin и настройте `PlayGamesPlatform.Activate()`
  в `GameManager` при старте.

## Сохранение данных

- `SaveManager` хранит один JSON-объект `PlayerProgressData` в `PlayerPrefs`
  под ключом `PuzzleGame_SaveData_v1`.
- Поля: текущие монеты/кристаллы/лайвы, время последней потери жизни (для
  расчёта восстановления), список прогресса по уровням (id, звёзды, лучший
  счёт), список количества усилений.

## Известные упрощения (осознанный выбор для MVP)

- Визуал плиток — сплошные цветные квадраты, генерируемые кодом
  (`TileSpriteFactory`), а не художественные спрайты — легко заменить,
  назначив `sr.sprite` в `Tile.Init` на свой ассет.
- Звук: `AudioManager` полностью готов к использованию, но клипы не
  прикреплены (опциональный пункт ТЗ) — добавьте `AudioClip` через инспектор
  или код и вызывайте `AudioManager.PlaySfx/PlayMusic`.
- Реклама и биллинг — интерфейс/заглушки готовы, реальные SDK не подключены
  (по ТЗ этого не требовалось).
- UI построен кодом (см. выше), а не статичными `.prefab`/`.unity` файлами —
  это осознанное архитектурное решение ради надёжности и воспроизводимости
  без доступа к редактору Unity при генерации проекта.
